clmesh_1018h0_props - individually-readable renders for 1018h0.str2_pc's
==========================================================================
smaller real `.clmesh_pc` props (Part 2 of the redispatched

NOT a golden-regression scene (no baseline_*/checkXScene() exists for this
directory - these PNGs are real, viewable OUTPUT, not a frozen byte-exact
baseline). Produced by the new `clmesh-batch` command
(runClmeshBatch(), tools/sr3_viewer.cpp).

Why this exists: HANDOFF.md Sec9.136's own `clmesh-tile` composite render
(runClmeshTile()) places every real prop in 1018h0.str2_pc on ONE shared-
scale grid with ONE shared camera distance - real geometry, real textures,
but a real, honestly-documented consequence of this population's own 200x+
real size range (0.24 units for a small streetlight up to 74 units for
airport_controltower.clmesh_pc) is that most of the smaller real props read
as only a few pixels tall next to the tower-scale prop's own footprint.
`clmesh-batch` gives each real prop its OWN individual capture, camera
auto-fit to THAT prop's own real local bounding box (the exact same
`buildOrbitViewProjection()` math the single-object `clmesh` command/
clmesh_lite_fixh's own golden scene already use, which computes
`distance = extent * distanceScale` from whatever bounds it is given) - so
a small streetlight and a large sign gantry both render as clear,
individually-readable images, at the SAME yaw/pitch/distanceScale framing
convention (34.4deg/20.1deg/1.80), not a per-tier bucketing scheme.
