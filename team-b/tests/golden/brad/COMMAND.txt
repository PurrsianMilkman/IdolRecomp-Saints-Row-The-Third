549/549 population-validated - HANDOFF.md Sec9.101-area), brad.ccmesh_pc/
brad.gcmesh_pc/brad.rig_pc entries within it.

Why this pose: `sr3_viewer pose` has exactly one built-in test pose (no

bone regression check this project has run since HANDOFF.md Sec9.13/
Sec9.62. It is deterministic (CPU skinning, no RNG, no wall-clock input)
and was independently re-verified byte-identical old-binary-vs-new-binary
across a real canonical-file change (HANDOFF.md Sec9.105, 2026-09-29):
bind MD5 289843206DB6F06976BC4EFECA0E162C, posed MD5
BCB280190B75E414B3FEB3D06D143734 - this baseline's two PNGs reproduce
those exact hashes.
