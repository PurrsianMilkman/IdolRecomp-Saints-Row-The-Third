## The golden-label failure, root-caused (not a flaky/transient issue)

`tools/golden_scene_check.cpp`'s `main()` added an unconditional `_putenv_s("SR3_FORCE_WARP", "1")` in
the earlier infra merge (`a001c05`). Every pre-existing golden baseline was frozen under real hardware
(RTX 3090) before that line existed, so ALL 10 pre-existing scenes now mismatch when compared against a
now-unconditionally-WARP-rendered capture — confirmed directly (not assumed): `city_corner`, which passed
earlier in this same session's own ctest run under hardware, now fails identically to `walk_demo`. This
is deliberate new behavior from B3, not a bug, a flaky GPU, or anything touched by probe-autopilot,
walk-demo, or sr3steam.

**Resolution in progress** (orchestrator's own decision, relayed after this was reported): goldens become
WARP-only permanently. A dedicated agent is migrating all scenes with a careful per-scene hardware-vs-WARP
tolerance comparison (visual + numeric), preserving each old hardware baseline under `<scene>_hw_pre_warp/`,
and adding a permanent `--hw`/`SR3_FORCE_HW=1` escape hatch for hardware-rendered review/demo images. Not
resolved as of this doc — tracked in HANDOFF.md.
